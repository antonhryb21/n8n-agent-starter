# Інфраструктура пакета n8n-agent-starter

Цей документ пояснює, як влаштована система, без зайвих технічних деталей. Його можна читати з будь-якого місця, але краще по порядку.

> Статус: документ погоджено 2026-10-16. Конфіги й скрипти створюються за [CHECKLIST.md](CHECKLIST.md).

---

## 1. Мета системи

Ти пишеш повідомлення своєму Telegram-боту, а він відповідає. Відповідь формує **n8n**, програма для автоматизацій, яка працює **на твоєму Mac**.

Навіщо це курсу: на цій основі ми далі додамо AI-агента. Бот стане "обличчям" агента, а n8n його "мозком".

---

## 2. Мінімальна архітектура

```
 Ти в Telegram
      │  1. пишеш повідомлення
      ▼
 Сервери Telegram
      │  2. пересилають повідомлення на публічну адресу (HTTPS)
      ▼
 Тунель ngrok  (https://твій-домен.ngrok-free.app)
      │  3. передає запит усередину твого Mac
      ▼
 n8n на твоєму Mac  (localhost:5678)
      │  4. workflow обробляє повідомлення
      ▼
 Telegram API
      │  5. n8n надсилає відповідь
      ▼
 Ти бачиш відповідь у чаті
```

Головна ідея: Telegram не може "достукатися" до твого комп'ютера напряму, бо він захований за домашнім роутером. Тунель дає йому публічну адресу, яка веде прямо в n8n.

---

## 3. Компоненти й роль кожного

| Компонент | Що це простими словами | Роль |
|---|---|---|
| **Telegram-бот** | твій бот, створений через @BotFather | вхідні двері: приймає повідомлення від людей |
| **Тунель (ngrok)** | "подовжувач" з інтернету до твого Mac | дає публічну HTTPS-адресу для Telegram |
| **n8n** | конструктор автоматизацій у браузері | отримує повідомлення, виконує логіку, надсилає відповідь |
| **Docker** | програма, що запускає n8n і тунель у "коробках" | все ставиться і запускається однаково на будь-якому Mac |
| **Файл `.env`** | записник із паролями | зберігає токени лише на твоєму комп'ютері |
| **Скрипти** | кнопки "Старт", "Стоп", "Перевірка" | щоб не вводити команди вручну |

---

## 4. Що працює локально (на твоєму Mac)

- **n8n**: його сторінка відкривається за адресою `http://localhost:5678`.
- **Дані n8n**: твої workflow, підключення (credentials) та історія запусків. Вони лежать у сховищі Docker і не зникають після вимкнення.
- **Програма тунелю**: вона сама встановлює з'єднання *з* твого Mac *до* ngrok. Тобі не треба відкривати порти на роутері.
- **Файл `.env`** з твоїми токенами.

Якщо вимкнути Mac або зупинити систему, бот перестане відповідати. Повідомлення, надіслані в цей час, Telegram збереже і доставить, коли система знову запуститься (зберігає до 24 годин).

---

## 5. Що бачить інтернет

**Має бачити:** лише адреси, на які Telegram надсилає повідомлення:
`https://твій-домен.ngrok-free.app/webhook/...`

**Не має бачити:** сторінку редагування n8n, твої workflow і налаштування.

Як ми це забезпечуємо:
1. Тунель пропускає тільки шляхи `/webhook/...` і `/healthz` (технічну перевірку). Усе інше він блокує відповіддю 403.
   - **ngrok**: це робить правило Traffic Policy, яке доступне й на безкоштовному тарифі (до 5 правил).
   - **Cloudflare Named Tunnel**: так само, через правило шляху в налаштуваннях тунелю.
   - **Cloudflare Quick Tunnel**: обмежити шляхи **не можна**, сторінка входу n8n буде видна з інтернету. Тому цей режим лише запасний і на короткий час.
2. Навіть якщо щось пройде, n8n вимагає логін і пароль власника. Пароль має бути надійним.
3. Сторінка n8n на твоєму Mac відкрита тільки для самого Mac, а не для інших пристроїв у твоїй Wi-Fi мережі.

---

## 6. Порти й адреси

| Адреса | Хто користується | Звідки доступна |
|---|---|---|
| `http://localhost:5678` | ти, щоб редагувати workflow у n8n | лише з твого Mac |
| `http://localhost:5678/healthz` | скрипт перевірки | лише з твого Mac |
| `http://localhost:4040` | ти, щоб бачити запити, що пройшли через тунель (панель ngrok) | лише з твого Mac |
| `https://твій-домен.ngrok-free.app/webhook/...` | сервери Telegram | з інтернету |
| `https://твій-домен.ngrok-free.app/healthz` | скрипт перевірки тунелю | з інтернету |

**Порт** схожий на номер квартири: адреса будинку (`localhost`) одна, а квартир багато. n8n "живе" у квартирі 5678. Telegram завжди стукає на стандартний порт 443 (HTTPS), а тунель переводить його на 5678.

## 7. Змінні середовища

Це налаштування у файлі `.env`. Скрипт `setup` створює цей файл сам і питає в тебе лише перші три значення.

| Змінна | Що це | Звідки взяти | Секрет? |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ключ доступу до твого бота | @BotFather → `/newbot` | **так** |
| `NGROK_AUTHTOKEN` | ключ твого акаунта ngrok | dashboard.ngrok.com → Your Authtoken | **так** |
| `NGROK_DOMAIN` | твоя постійна адреса тунелю (`щось.ngrok-free.app`) | dashboard.ngrok.com → Domains | ні |
| `COMPOSE_PROFILES` | який тунель запускати: `ngrok`, `cloudflare-quick` або `cloudflare-named` | `setup` питає, за замовчуванням `ngrok` | ні |
| `CLOUDFLARE_TUNNEL_TOKEN` | ключ Cloudflare Named Tunnel (лише для цього режиму) | Cloudflare Zero Trust → Networks → Tunnels | **так** |
| `CLOUDFLARE_HOSTNAME` | твоя адреса в Cloudflare, напр. `bot.example.com` (лише для цього режиму) | налаштування тунелю | ні |
| `N8N_ENCRYPTION_KEY` | ключ, яким n8n шифрує збережені токени | генерує `setup` автоматично | **так** |
| `WEBHOOK_URL` | публічна адреса для n8n, `https://` + `NGROK_DOMAIN` | складається автоматично | ні |
| `GENERIC_TIMEZONE` | часовий пояс, за замовчуванням `Europe/Kyiv` | можна не міняти | ні |
| `N8N_VERSION` | зафіксована версія n8n | задана в пакеті | ні |

Шаблон з назвами, але без значень, лежить у репозиторії як `.env.example`.

## 8. Правила для секретів

1. **Секрети живуть лише у `.env`** на твоєму комп'ютері (і в сховищі n8n у зашифрованому вигляді).
2. **`.env` ніколи не потрапляє в git.** Він прописаний у `.gitignore`, а перевірка `secrets-check` і GitHub-перевірка (CI) зупинять коміт, якщо в ньому знайдеться токен.
3. **Не надсилай токени** в чати, скріншоти чи Google Docs. Якщо на скріншоті видно токен, зафарбуй його.
4. **Якщо токен потрапив у чужі руки**, одразу заміни його:
   - Telegram: @BotFather → `/revoke`, потім онови `.env` і credential у n8n;
   - ngrok: dashboard → Authtoken → Reset, потім онови `.env`.
5. **Не губи `N8N_ENCRYPTION_KEY`.** Без нього n8n не зможе прочитати збережені підключення, і доведеться вводити їх заново.
6. **Експорт workflow безпечний**: n8n не додає токени у файли експорту. Але перед тим як ділитися файлом, все одно запусти `secrets-check`.

## 9. Обраний тунель і запасний варіант

Пакет підтримує три режими. Перемикаються вони одним рядком у `.env` (`COMPOSE_PROFILES`), решта лишається без змін.

**Основний: ngrok (`ngrok`).**
- Безкоштовний акаунт ngrok дає одну постійну адресу виду `щось.ngrok-free.app`. Telegram запам'ятовує її один раз, і бот працює після кожного перезапуску.
- Домен і DNS не потрібні.
- Ліміти безкоштовного тарифу: 20 000 запитів і 1 ГБ трафіку на місяць. Навчальному боту цього вистачає з великим запасом.
- Для браузера ngrok показує сторінку-попередження, але на Telegram вона не впливає.

**Запасний: Cloudflare Quick Tunnel (`cloudflare-quick`).**
- Не потрібен акаунт, працює одразу.
- Мінус 1: адреса змінюється при кожному запуску. Скрипт `start` сам підставляє нову адресу і перезапускає n8n, а тобі треба вимкнути й увімкнути workflow (перемикач Active), щоб Telegram дізнався нову адресу.
- Мінус 2: не вміє обмежувати шляхи (див. розділ 5).
- Коли використовувати: ngrok тимчасово недоступний або не вдається створити акаунт.

**Найстабільніший: Cloudflare Named Tunnel (`cloudflare-named`).**
- Постійна адреса на твоєму домені, без лімітів трафіку і без сторінок-попереджень.
- Потрібен куплений домен, доданий у Cloudflare, і разове налаштування тунелю в панелі Cloudflare ([docs/05-cloudflare.md](docs/05-cloudflare.md)).
- Коли використовувати: викладачу, або коли бот має працювати довго й надійно.

## 10. Як запускати систему

**Перший раз (один раз, близько 20 хвилин):**
1. Встанови **Docker Desktop для Mac** (обери свій чип: Apple Silicon або Intel) і запусти його. Дочекайся зеленого статусу "Engine running".
2. Створи бота в Telegram через **@BotFather** і скопіюй токен.
3. Зареєструйся на **ngrok.com**, скопіюй Authtoken і свою адресу з розділу Domains.
4. Двічі клацни **`Setup.command`** у папці пакета й встав три значення, коли попросить.
5. Двічі клацни **`Start.command`**. Відкриється `http://localhost:5678`: створи акаунт власника n8n з надійним паролем.
6. У n8n імпортуй `workflows/telegram-echo.json`, обери в ньому credential з токеном бота і натисни **Active**.
7. Напиши боту "привіт".

**Кожен наступний раз:**
1. Запусти Docker Desktop.
2. Двічі клацни `Start.command`.

> Якщо macOS не відкриває `.command`-файл і пропонує лише **Перемістити в Корзину** або **Готово**: натисни **Готово** і один раз виконай у Terminal `xattr -dr com.apple.quarantine ` + перетягни папку пакета ([docs/01-setup.md](docs/01-setup.md#4-завантаж-пакет)).

---

## 11. Як зупиняти систему

- Двічі клацни **`Stop.command`**.
- Твої workflow і налаштування збережуться. Наступний `Start` продовжить з того самого місця.
- Docker Desktop можна закрити після зупинки, щоб звільнити пам'ять.

Повне скидання (видаляє всі workflow і дані n8n) у пакеті є окремою командою `scripts/reset.sh`. Вона двічі перепитує, перш ніж щось видалити.

## 12. Як зрозуміти, що все працює

**Швидка перевірка:** написати боту й отримати відповідь.

**Повна перевірка:** двічі клацнути **`Check.command`**. Він покаже список:

```
✅ Docker запущений
✅ n8n працює на localhost:5678
✅ Тунель відповідає з інтернету
✅ Токен бота правильний
✅ Telegram знає правильну адресу webhook
✅ Сторінка n8n закрита для інтернету
```

Біля кожного ❌ буде підказка, що зробити. Найчастіші проблеми:

| Що бачиш | Причина | Що робити |
|---|---|---|
| ❌ Docker запущений | Docker Desktop закритий | відкрий Docker Desktop, дочекайся зеленого статусу |
| ❌ Тунель відповідає | неправильний authtoken або домен | перевір значення в `.env`, перезапусти `Start` |
| ❌ Токен бота | помилка при копіюванні | скопіюй токен з @BotFather ще раз |
| ❌ Адреса webhook | workflow не активний | у n8n увімкни перемикач **Active** |
| Бот мовчить, все ✅ | помилка всередині workflow | n8n → **Executions**, відкрий останній запуск |

Також корисно: `http://localhost:4040` показує кожен запит від Telegram, що пройшов через тунель.

## 13. Як потім перенести на VPS

VPS — це орендований сервер в інтернеті, що працює цілодобово. Тоді бот відповідає, навіть коли твій Mac вимкнений.

**Що змінюється:**

| Зараз (локально) | На VPS |
|---|---|
| n8n у Docker на Mac | той самий n8n у Docker на сервері (той самий `docker-compose.yml`) |
| тунель ngrok дає адресу | власний домен (наприклад, `bot.example.com`) вказує на IP сервера |
| HTTPS дає ngrok | HTTPS дає **Caddy**, він сам отримує безкоштовний сертифікат |
| `WEBHOOK_URL=https://...ngrok-free.app` | `WEBHOOK_URL=https://bot.example.com` |
| SQLite (файл) | бажано **Postgres** (надійніше для постійної роботи) |
| `.env` на Mac | `.env` на сервері, теж не в git |

**Що лишається без змін:** workflow, логіка бота, правила секретів, змінні середовища (крім адреси), тести.

**Кроки переносу (коротко):**
1. Орендувати VPS (Ubuntu, 2 ГБ RAM) і купити домен.
2. Вказати домен на IP сервера (DNS-запис типу A).
3. Встановити Docker на сервері, скопіювати пакет через git.
4. Замість сервісу тунелю ввімкнути сервіс Caddy (у пакеті буде готовий варіант compose для VPS).
5. Створити `.env` на сервері, змінити `WEBHOOK_URL` на свій домен.
6. Експортувати workflow з локального n8n, імпортувати на сервері, ввести credentials, натиснути **Active**.
7. Закрити на сервері всі порти, крім 80 і 443 (фаєрвол), налаштувати резервні копії.
8. Запустити `check` на сервері.

**Альтернатива без відкритих портів:** лишити на VPS Cloudflare Named Tunnel замість Caddy. Сервер тоді взагалі не приймає вхідних з'єднань напряму.
