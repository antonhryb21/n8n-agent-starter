# 02. Перший workflow

Мета: бот повторює твоє повідомлення. Так ми переконуємось, що весь ланцюжок Telegram → тунель → n8n → Telegram працює.

## 1. Запусти систему

1. Переконайся, що Docker Desktop запущений (статус **Engine running**).
2. Двічі клацни **`Start.command`**.
3. Дочекайся повідомлення `✅ n8n готовий` і адреси тунелю. Браузер сам відкриє `http://localhost:5678`.

## 2. Створи акаунт власника n8n

Тільки під час першого запуску.

1. Введи email, ім'я та **надійний пароль** (від 12 символів). Цей акаунт захищає твій n8n.
2. Анкету про компанію можна пропустити.
3. Якщо з'явиться вікно **Connect a model** (AI-помічник n8n), закрий його хрестиком. Для курсу воно не потрібне: йому потрібен платний ключ, і він надсилає твої workflow провайдеру.

## 3. Імпортуй workflow

1. У n8n натисни **Create Workflow** (або **+** → **Workflow**).
2. Меню **⋯** справа вгорі → **Import from File**.
3. Обери файл `workflows/telegram-echo.json` з папки пакета.

Ти побачиш два вузли: **Telegram Trigger** (отримує повідомлення) і **Reply** (надсилає відповідь).

## 4. Підключи бота

1. Двічі клацни вузол **Telegram Trigger**.
2. У полі **Credential to connect with** обери **Create New Credential**.
3. Встав **токен бота** в поле **Access Token** → **Save**.
4. Відкрий вузол **Reply** і обери той самий credential.

## 5. Увімкни workflow

1. Натисни **Save**.
2. Перемкни **Inactive → Active** справа вгорі.

У цей момент n8n сам повідомляє Telegram адресу, куди надсилати повідомлення.

## 6. Перевір

Напиши своєму боту в Telegram `привіт`. Він має відповісти `Ти написав: привіт`.

Не відповідає? Двічі клацни **`Check.command`** і подивись [03-troubleshooting.md](03-troubleshooting.md).

## Важливо: тестовий і робочий режим

У Telegram Trigger є кнопка **Listen for test event**. Вона тимчасово перемикає бота на тестову адресу. Поки workflow **Active**, нею користуватися не треба: після тесту бот може перестати відповідати. Якщо так сталося, вимкни й знову увімкни перемикач **Active**.
